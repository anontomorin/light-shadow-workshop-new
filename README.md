# 光影工坊：窗棂之间

> 一个把**中国传统建筑窗棂**与**真实几何投影**放在同一张画布上的浏览器创作工具 + 益智游戏。

界面与配色按**中国风**重做：宣纸底、墨色字、朱砂点缀、碧玉与木色构件。今年这一版把游戏 / 实验室界面整体推成**夜色工坊**：暗漆底、鎏金线与朱砂印章，三维场景里是深木画框、暖冷双色布光与暗漆影壁；标题页与二级入口用**生成式夜色山水**作背景。标题与题签使用**马善政毛笔楷书**、正文使用**站酷小薇**，两者的**中文子集 woff2 已内嵌进仓库**（`src/fonts/`），断网也能正常显示；其余装饰（回纹角、印章、窗棂暗纹）仍是纯 CSS / 内联 SVG。

首页把主入口留给创作，两个以"影子"为核心的玩法收进二级入口：

| 层级 | 入口 | 内容 |
|---|---|---|
| 首页 | **花窗工坊** | 从传统纹样模板出发，调参数、自绘棂条、移动窗格，实时看见窗棂空隙投出的镂空影子，导出 1920×1080 海报 |
| 首页 | **纹样图鉴** | 三种传统纹样的结构说明、本项目如何生成、可点击的来源链接 |
| 首页 | **光影挑战**（二级入口） | 影形解谜（**10 关**）与自由实验室（**13 种形状**）都收在这里 |
| 首页 | **作品与资料** | 技术要点、文化资料来源、**已知边界**（如实写明不是文物精确复原） |

- **影形解谜**：移动、旋转几何物体与**花窗构件**并调整点光源，让墙上的影子与目标轮廓重合。前 6 关是几何入门（方块 → 圆盘 → 飞鸟 → 城市天际线），**第 7–10 关的题目取自经典花窗**：方格窗十字棂、菱花窗三交六椀、冰裂纹、窗棂总成圆光窗。
- **自由实验室**：不设目标、不评分的沙盒，13 种形状可选 —— 除三角/方形/圆形/六边/菱形/长方外，新增五边形、八边形、梯形、半圆，以及**十字形、五角星、圆环**这三个带镂空的凹形。

墙上的影子**不是贴图、不是预设动画、不是随机进度条**：它是每一个构件先被分解成凸块，每块各自经点光源投影、逐块求凸包，再做多边形并集光栅化得到的真实掩码。**格子之间的空隙同样是判定的一部分**，必须真的对上。

- **技术栈**：Vite 5 + TypeScript 5.6 + Three.js 0.169（渲染）+ Canvas 2D（掩码与海报）
- **运行形态**：纯前端，无后端、无账号、无数据库、无外部 CDN，运行时依赖只有 `three`
- **在线试玩**：<https://anontomorin.github.io/light-shadow-workshop/>

## 二、操作方法

桌面端以鼠标为主，键盘为辅。

### 2.1 标题页导航

首页只有四个一级入口，"闯关"与"试手"两种玩法收在二级入口「光影挑战」里：

| 按钮 | 进入 |
|---|---|
| **进入花窗工坊** | 窗棂创作工具（首页主入口） |
| **纹样图鉴** | 三种传统纹样的结构说明、本项目如何生成、来源链接 |
| **光影挑战** | 二级入口页：**影形解谜**（10 关）/ **自由实验室**（13 种形状）两张卡片 |
| **作品与资料** | 技术要点、文化来源、已知边界 |

二级入口页的两个卡片各自带一个主按钮：`进入关卡` → 影形解谜关卡选择页；`进入实验室` → 自由实验室。影形解谜关卡选择页右上角也留了一个 `自由实验室` 按钮，从任意一处都能直达。

首页右侧是**三扇花窗的轮播**：每 4.2 秒交叉淡入下一扇（步步锦 → 冰裂纹 → 三交六椀菱花），标题右侧的**朱砂印章显示当前窗棂样式名**，下方的三个菱形指示点可点击手动切换（点过之后计时重新开始）。三扇窗都由工坊里同一个纹样生成器实时画出，不是什么预制图。若系统开启了「减少动态效果」，则停在第一扇不自动切换。

### 2.2 影形解谜 / 自由实验室

| 操作 | 行为 |
|---|---|
| 左键点击物体 | 选中物体，显示高亮描边 |
| 按住左键拖动 | 在操作平面内移动选中物体，影子实时跟随 |
| `Q` / `E` | 选中物体逆时针 / 顺时针旋转 5°（按住 `Shift` 为 15°） |
| 方向键 | 微调选中物体位置（0.04 世界单位；`Shift` 为 0.18） |
| 右侧面板滑杆 | 调整选中物体的**面内角度**、**翻转**与**深度** |
| 光源控制滑杆 | 调整光源**水平位置**、**高度**、**距离** |
| **右键拖动** | **环绕观察** |
| `Shift` + 右键 / 中键拖动 | 平移观察中心 |
| 滚轮 | 缩放视角 |
| `R` / `H` / `Esc` | 重置 / 提示 / 暂停或返回 |

**观看视角**可自由改变：水平角 `[-62°, 80°]`、俯仰角 `[8°, 70°]`、距离 `[13, 40]`。这些约束保证相机始终位于投影墙**前方**且高于地面。切换视角**不影响**投影计算与匹配判定。

**通关规则（严格）**：墙上影子的 IoU 达到本关阈值，且**连续 3 次校验**均达标才通关。粗略摆放（约 ±0.12 世界单位）**不足以通关**，必须精修到约 ±0.09 以内。

画布右上角的 **「模板栏 / 参数栏」** 两个开关可以把任意一侧收起；两侧都收起时画布会铺满整行

**操作指引**（画布左上角的常驻卡片，可一键收起）分两部分：

- **四步上手**：选纹样 → 摆窗格 → 调影子 → 带走它；

| `滚轮` | 拉近 / 推远（距离限制在 13–40） |

| 右栏「投影辅助」 | 示意光线 / 包围盒 / 目标网格 开关 |
| 右栏「文化卡片」 | 当前模板的形态说明与可点击的来源链接 |
| 右栏「引导实验」 | 选一个实验，工具记录基准并给出**实时对照读数** |
| 底部「画棂条」 | 进入 / 退出自绘模式：`单击` 加节点，`双击` / `Enter` 完成一笔，`Esc` 取消（折线为空时退出绘制）；支持吸附网格。绘制中会显示**节点序号、当前节点准星、下一段橡皮筋与真实粗细的棂条预览** |

**引导实验**有四个：同一扇窗影子为什么变大（深度）、平移窗格影子怎么走、旋转窗格的影子变化、密度对镂空的影响。每个实验会记录基准快照并持续显示「基准 → 当前（变化 %）」，叙述文本完全由实时指标推导，不含写死的结论。

## 三、核心机制：镂空是怎么保留下来的

这是本项目最关键的技术点，也是它区别于"把一张窗棂贴图贴到墙上"的地方。

### 3.1 问题

最朴素的做法是把一个物体的**全部**投影点求一次凸包，得到一个多边形。

这对实心方块是对的，但一旦形状里有凹陷或孔洞就彻底失效：

```
十字形     → 整块凸包会把四个凹角填平
五角星     → 整块凸包会把五个星角之间的内凹填平
圆环       → 整块凸包会把中间的孔填死
一扇花窗   → 整块凸包会把所有窗格空隙填死，影子变成一块实心方块
```

这不是"不够好看"的问题，而是**判定层面的致命错误**：目标轮廓是有孔的，玩家永远匹配不上一个无孔的实心块。

### 3.2 做法：凸块分解 + 逐块凸包 + 并集

**每个物体先被分解成若干"凸块"，凸包只允许在单个凸块内部求**：

```
ShapeType ──(GeometryFactory.buildBaseParts)──► 凸块顶点数组 Pt[][]
  十字形 → 3 个矩形（竖臂 + 左臂 + 右臂，互不相交，并集 = 十字形本身）
  五角星 → 1 个内五边形 + 5 个外三角（内五边形的边就是星形的真实凹边界）
  圆环   → 18 个凸环扇块（扇块用割线多边形近似圆环，面积误差 < 0.5%）
  圆形   → 1 个 48 边形       方块 / 三角 / 六边 / 菱 / 五边 / 八边 / 梯形 / 半圆 / 长方 → 1 个凸多边形
  棂条   → 1 个矩形（工坊里的窗棂则由 WindowDocument 逐根杆件拆分）

ShadowObjectDefinition ──► ShapePart[]   每个构件可带 dx/dy（面内平移）、rot（面内旋转）、w/h（目标宽高）
   ▼  每个 part 各自求凸包（convexHull 的契约就是"只对单个凸块调用"）
局部顶点（每个凸块一组）
   ▼  × matrixWorld → projectPoint(light, world, WALL_Z)     t=(Lz−Zw)/(Lz−Pz)
墙面点
   ▼  convexHull() 逐块 → clipPolygonToWall() 逐块
Point2[][]（N 个多边形，N ≥ 凸块总数）
   ▼  SilhouetteRasterizer.rasterize(polygons)       并集：像素落在任意一个多边形内即为 1
二值掩码 288×160 → IoU 判定 / 读数 / 墙面渲染 / 海报
```

**镂空为什么能保留**：孔洞处没有任何凸块的多边形覆盖，掩码恒为 0。
**交叉处为什么看不出接缝**：并集语义下重叠区域只算"有影子"一次。

墙面渲染用**模板缓冲并集**：所有投影多边形先作为"印章"写进 stencil，再用一个墙面平面按 `stencilRef` 只在被标记的像素上铺色 —— 重叠区只铺一次色，颜色完全均匀。层序由 `renderOrder` 显式钉死（three 对共面透明对象的"按相机距离排序"不稳定）。

### 3.3 为什么测试不可能骗人

`npm run verify:window` 不只断言"正确实现保留了镂空"，还**同时构造错误实现并断言它确实会失败**：

| 断言 | 实测 |
|---|---|
| 空白窗格（仅外框）投影后中央空隙全为 0 | 中央 21×21 px 填充 **0** |
| **错误实现（整窗一次凸包）确实会把中央空隙填满** | 中央 21×21 px 填充 **441** |
| 正确实现保留的镂空面积显著更高 | 错误 6724 px vs 正确 1670 px |
| 步步锦投影镂空率 > 25% | **52.2%** |
| 相邻杆件交叉处合并为实心 | 交叉点 7×7 px 填充 **29** |
| 格心保持镂空 | 格心探针 5×5 px 填充 **0** |
| **十字形**：逐块并集 vs 整块凸包 | **4860 px** vs 7104 px（差 2244 px，就是四个凹角） |
| **五角星**：逐块并集 vs 整块凸包 | **3208 px** vs 6160 px（差 2952 px，就是五个内凹） |
| **圆环**：逐块并集 vs 整块凸包 | **4708 px** vs 7224 px（差 2516 px，就是中间的孔） |
| 每个凸块自身都是凸的（`convexHull(p)` 面积 == `p` 面积） | 14 种形状全部成立（凸块数：十字 3 / 五角星 6 / 圆环 18，其余 1） |
| 形状基准尺寸与真实轮廓一致（`w` / `h` 换算不会被悄悄拉伸） | 14 种形状全部一致 |
| 四道花窗题目的**格眼被如实保留** | 第 7/8/9/10 关分别为 **2 / 4 / 9 / 12** 个独立镂空；5448 vs 13600、6880 vs 14960、5584 vs 14268、7704 vs 16864 px |

这一组断言让"第一条断言"不可能因为探针位置选错而变成**永远成立的空断言**。

### 3.4 显示 / 判定 / 导出共用同一份数据

工坊里同时存在两条投影路径，它们的输出必须**逐点一致**（`verify:window` 会断言）：

| 路径 | 数据来源 |
|---|---|
| 解析式 `projectParts(局部顶点, 变换, 光源)` | 节点里算出来的解析顶点（Node 可直接测） |
| 渲染路径（遍历真实 Mesh） | `geometry.attributes.position` + `matrixWorld` |

之所以能一致，是因为**渲染用的顶点本身就是解析式算出来的**：所有凸块共享一份缓存的 `ExtrudeGeometry`（键为 `type#index`），通过 `position` / `rotation.z` / `scale` 摆放，其世界角点恰好等于解析式算出的同一组值。

比对方式也说明了这条断言的强度：**逐凸块做点集比对**（`dedupePoints()` 后 `pointSetsMatch()`，容差 1e-5），再叠加**整关掩码级 IoU ≥ 0.9995**。之所以不直接比对"凸包顶点序列"，是因为挤出几何在端面三角化与侧壁处会输出重复顶点，且薄扇块上常有三点近似共线，`convexHull` 的成员判定会在 1e-7 量级翻转——**那是数值噪声，不是投影算错**。

PNG 海报**不复用 WebGL 画布像素**，而是用 `renderPoster()` 走纯 Canvas 2D：左侧用 `barPlanCorners()` 画设计图，右侧直接绘制 `this.polygons`（与墙面渲染**同一个数组**），失败时兜底绘制 `this.mask`（与 IoU 判定**同一个掩码**）。所以屏幕上的影子、判定用的掩码、海报上的窗影，三者数学上必然一致。

> 完整推导、边界情况（深度安全余量 `MIN_LIGHT_GAP = 2.0`、凹形只支持"凸块分解"而非任意布尔运算、层序为何必须用 `renderOrder`）见 [`docs/技术说明与核心算法.md`](docs/技术说明与核心算法.md)。

### 3.5 关卡题目也是这套模型

四道花窗题目不是贴图，而是用**构件工具箱**拼出来的复合物体：

```ts
slat(w, h)                       // 一根水平的（h > w 则为竖直的）矩形棂条
rhombus(w, h)                    // 一个菱形（旋转 45° 的方块）
frame(halfW, halfH, t)           // 四面外框，由 4 根棂条组成
rosette(coreW, coreH, ringR, petalW, petalH, count, startDeg)
                                 // 花心：中心一圈 + 外围花瓣
```

第 8 关的三交六椀菱花 = `frame` + 3 根相差 60° 的长棂条 + `rosette(...)`；第 10 关的圆光窗 = `frame` + 井字格（2 根）+ 菱格（2 根斜棂）+ 一个 `ring`（圆环）。所有构件都是 `ShapePart`，因此"窗框的孔"、"圆环的孔"、"棂条交叉处的实心"三件事由同一段代码保证。

## 四、几何投影公式

坐标约定：`X` 为墙面水平方向，`Y` 为垂直方向，`Z` 为深度方向，投影墙位于 `Z = 0`，点光源位于正 `Z` 端。

设点光源 `L = (Lx, Ly, Lz)`，顶点 `P = (Px, Py, Pz)`，墙平面 `z = Zw`，则射线与墙面交点 `Q`：

```text
t  = (Lz - Zw) / (Lz - Pz)
Qx = Lx + t * (Px - Lx)
Qy = Ly + t * (Py - Ly)
```

实现要点（`src/projection/Projector.ts`）：

- **顶点变换**：局部顶点经 `Matrix4` 得到世界坐标；
- **异常保护**：`|Lz − Pz| < 1e-4` 时返回 `null` 丢弃该顶点；全局另有深度安全余量 `MIN_LIGHT_GAP = 2.0`；
- **轮廓取凸包**：Andrew monotone chain。`convexHull()` 的调用契约是**只对单个凸块调用**（函数注释里写明了），所以"凸包"不会破坏凹陷与孔洞；
- **墙面裁剪**：Sutherland–Hodgman 裁到墙面矩形（逐凸块裁）。

对外只暴露一个入口：

```ts
export function projectParts(
  localParts: THREE.Vector3Like[][],   // 每个凸块一组局部顶点
  transform: Transform3D,              // 物体的位移 / 三轴旋转 / 缩放
  light: THREE.Vector3Like,
  scale = 1,
  wallZ: number = WALL_Z,
): Point2[][]
```

关卡、实验室、工坊三条玩法都调它；工坊则传入"每一根杆件一个凸块"的数组。

> 这是针对指定几何体的**几何投影计算**，**不是**完整的光学仿真，不涉及波长、干涉、衍射、焦距、半影。

## 五、轮廓匹配

`src/projection/SilhouetteRasterizer.ts` + `SilhouetteMatcher.ts`：

1. 墙面取 `18 × 10` 世界单位，映射到 `288 × 160` 离屏 Canvas。`18/288 = 10/160 = 0.0625`，即**每个像素恰好对应各向同性的世界尺度**，IoU 不受方向影响。
2. 当前影子与目标轮廓使用**同一套 `wallToMask` 坐标映射**。
3. 多边形纯色填充 → 读像素 → 按 Alpha 阈值二值化。
4. `IoU = 交集像素数 / 并集像素数`。
5. **节流**：拖动中用降采样预览，松手后完整校验。
6. **目标轮廓固定**：目标掩码在关卡加载时一次性生成，**不随玩家操作变化**。
7. **防误判**：需要连续 3 次达标（`REQUIRED_CONSECUTIVE_HITS`）。

| 关卡 | 通关 | 优秀 | 大师 | 建议操作 | 粗对齐实测 | 精对齐实测 | 离散控件可达 | 目标影子面积 |

| 2 角度的秘密 | 0.79 | 0.83 | 0.85 | 22 | 0.713 | 0.866 | 0.960 | 1139 px |
| 3 远近之间 | 0.81 | 0.85 | 0.87 | 26 | 0.749 | 0.888 | 0.965 | 2417 px |
| 4 组合的艺术 | 0.83 | 0.87 | 0.89 | 44 | 0.775 | 0.906 | 0.994 | 2838 px |
| 5 飞鸟的轮廓 | 0.80 | 0.84 | 0.86 | 46 | 0.727 | 0.871 | 0.931 | 1942 px |
| 6 光影之城 | 0.83 | 0.87 | 0.88 | 68 | 0.776 | 0.892 | 0.978 | 9147 px |
| 7 方格窗 · 十字棂 | 0.69 | 0.72 | 0.75 | 52 | 0.523 | 0.768 | 0.964 | 5448 px |
| 8 菱花窗 · 三交六椀 | 0.69 | 0.72 | 0.74 | 58 | 0.519 | 0.762 | 0.941 | 6880 px |
| 9 冰裂纹 · 碎影 | 0.67 | 0.70 | 0.72 | 64 | 0.473 | 0.734 | 0.938 | 5584 px |
| 10 窗棂总成 · 圆光窗 | 0.70 | 0.73 | 0.76 | 78 | 0.534 | 0.778 | 0.958 | 7704 px |

**为什么花窗题目的阈值（0.67–0.70）比几何关（0.79–0.83）低？** 这是一个**几何性质，不是放松要求**：棂条是细长条，同样的 ±2° 角度误差在细条上造成的轮廓偏移相对条宽的比例远大于实心方块（方块只有四个角会偏，细条整条都在偏）。实测第 7–10 关的精对齐 IoU 只有 0.73–0.78，若强行沿用 0.83 就变成**不可达**——那才是作弊。因此阈值按实测重新标定，同时保持三条硬约束全部成立：粗对齐 < 通关 ≤ 离散控件可达 ≤ 精对齐 < 大师。

`npm run verify` 会为每关（**10 关全部**）：生成目标掩码做 ASCII 预览 → 置为目标参数验 IoU ≈ 1.0 → 施加两档扰动并断言阈值关系 → **离散控件可达性**（把目标吸附到玩家实际能摁出的最小粒度，IoU 必须仍 ≥ 通关阈值，实测 0.93–0.999）→ 恢复初始状态 → 校验深度合法性与是否贴边。

10 关目标状态实测 IoU **全部为 1.0000**。

## 十一、已知限制

**已实现**：**10 个完整关卡**（含 4 道经典花窗题目）与解锁、提示、三档评价、本地存档、物体/光源/视角控制、
**自由实验室（13 种形状，含十字形 / 五角星 / 圆环三个凹形镂空）**、
**花窗工坊**（3 种传统纹样 + 回纹边饰 + 空白模板、参数化重建、自绘棂条、引导实验、真实投影读数、
作品保存与读取、1920×1080 PNG 海报导出）、纹样图鉴与来源追溯、二级入口分层、
**中国风界面（夜色工坊 / 内嵌主题字体 / 生成式背景）**、四界面共用同一渲染器。

**已知限制：**

- **投影是几何投影模型**，非真实光学仿真；不模拟焦距、半影、折射、干涉。
- **凸包的调用契约是"只对单个凸块调用"**。当前 14 种形状中的凹形（十字 / 五角星 / 圆环）都做了凸块分解，
  因此"逐块凸包 + 并集"对它们**精确成立**。但这套模型**不支持任意布尔运算**：
  目前没有"用 A 减去 B"这类通用差集能力，新凹形必须手工给出凸块分解（并在 `verify:window` 里被断言"每块都是凸的"）。
- **圆环用 18 个凸扇块近似**，不是精确圆弧（面积误差 < 0.5%）。需要更精细时可提高 `RING_SEGMENTS`，
  代价是多边形数线性上升。
- **工坊的解析式投影**要求杆件是"轴对齐长方体 + 绕 Z 单轴旋转"。窗格整体旋转通过 `matrixWorld` 施加，
  两条路径都吃这个矩阵，因此不受影响；但若将来允许单根杆件绕 X/Y 自转，两条路径会分叉。
- **观看视角被约束在投影墙前方**（水平角 `[-62°, 80°]`、俯仰角 `[8°, 70°]`、距离 `[13, 40]`），
  不能转到墙背面——这是刻意设计，避免玩家看到镜像的影子。
- **花窗题目的阈值（0.67–0.70）低于几何关（0.79–0.83），这是几何性质而非放水**：
  细长棂条的轮廓对角度误差远比实心方块敏感，实测精对齐上限只有 0.73–0.78。阈值按实测重新标定，
  且"粗对齐 < 通关 ≤ 离散控件可达 ≤ 精对齐 < 大师"四条硬约束全部成立。
- **窄屏适配为响应式布局**（1440 / 1180 / 1024 / 560 px 断点），**未做移动端触控专门适配**；
  ≤1024px 时工坊改为「三维操作区在最上、两侧栏堆在下方」的单列结构，画布仍优先占据 54vh；
  工坊与标题页在窄屏下会自动改为单列，但自绘工具仍以鼠标为主。
- 仅在桌面端近年版本 Chrome 实测通过（无头 Chrome + SwiftShader 跑完整 175 项）；Firefox / Safari / Edge 建议实机复测。
- **未实现**：XR / AR、多玩家、云同步、账号系统、外部 CDN、第二引擎；影子截图以外的高级编辑（贝塞尔曲线棂条、对称/阵列工具）。
