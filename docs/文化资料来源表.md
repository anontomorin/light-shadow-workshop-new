## 一、使用与引用规则（先读这一节）

1. **文化卡片必须保留来源链接。** 界面上每条资料卡都会渲染出可点击的来源 URL 与发布机构，不允许只写"据资料记载"。
2. **不能从单篇文章推演来源未明确说明的历史结论。** 例如某页面只说了"由三根棂子交叉相接"，就不能据此推断它出现的年代、地域或象征含义。
3. **生成器参数化形态属于数字再设计。** 程序生成的几何不直接等于文物实物的精确形制，凡属程序生成的成果一律标注 **"数字示意"** 或 **"风格化创作"**（见第四节声明文案）。
4. **图像来源须可追溯。** 三维画面、判定掩码、海报与界面装饰全部由程序实时渲染或程序绘制（Canvas / SVG）；另有 **3 张 AI 文生图氛围底图**（首页、二级入口 / 关卡页、工坊侧栏），已在使用说明与第六节如实列明来源与处理方式。不引入任何来源不明的照片、插画或三维贴图。
5. **本表不是法律意见**，也不替代赛事官方参赛指南中的内容版权与生成式 AI 披露要求。

## 四、程序内的声明文案（原文）

这些文案硬编码在 `src/culture/patternCatalog.ts` 中，会原样出现在界面上：

- **`DIGITAL_MODEL_NOTE`（数字示意）**
  > 本模板是依据公开资料整理的参数化数字示意（教学简化模型），不是对任何具体文物或建筑构件的精确复原。
- **`STYLE_MODEL_NOTE`（风格化创作）**
  > 本模板为受传统冰裂纹窗棂几何构成启发的风格化数字创作，生成结果每次可按种子复现，但不代表唯一传统标准图样。
- **`USER_MODEL_NOTE`（用户创作）**
  > 这是用户自绘内容，属于个人创作，不代表任何传统窗棂形制，也未使用历史纹样名称或寓意。

对应的界面位置：

| 位置 | 展示内容 |
|---|---|
| 纹样图鉴（标题页 →「纹样图鉴」） | 每张卡片右上角有 **"数字示意"** 徽标；卡片内分「结构特点 / 本项目怎样生成 / 来源记载的语境 / 数字说明 / 来源」五个字段 |
| 花窗工坊右栏「文化卡片」 | 随当前模板切换，实时显示对应卡片与全部来源链接 |
| 「作品与资料」页 | 完整来源清单 + **已知边界**说明（含"不支持任意布尔运算""圆环为 18 段近似""教学简化模型"等） |
| 关卡选择页（花窗影谜分组） | 四道花窗题目的标题（方格窗 · 十字棂 / 菱花窗 · 三交六椀 / 冰裂纹 · 碎影 / 窗棂总成 · 圆光窗）取自第 2、3、4、7 条来源所述的窗式名称；关卡内的几何是**本项目自创的参数化构件**，用来体现构成方式，**不是某一扇具体古窗的复原图** |
